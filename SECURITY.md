# Security Policy

Do not report security or privacy vulnerabilities in public issues. Use the
repository's private security advisory reporting channel instead. Include a
minimal synthetic reproduction where possible and never include credentials,
account facts, runtime databases, logs, backups, or provider responses.

Maintainers will acknowledge reports and coordinate remediation through that
private channel.

## Official Project Boundary

The maintained project is single-user decision support, not a public
recommendation service, and contains no order-writing capability. These are
official-project safety invariants, not Apache-2.0 license restrictions on
forks. Forks are not maintained, qualified, activated, or endorsed by the
official project.
